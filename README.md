# figma-tools

A Figma plugin (plus a small build script) that imports design tokens into Figma as variable collections. Each collection is described by a JSON file, and you choose which ones to import each time you run the plugin.

## What it does

Ships with three collections:

- **Tailwind Spacing** — the full Tailwind v4 scale (0–96), a single "Default" mode, fixed px values.
- **Utopia Spacing** — fluid spacing tokens generated by [Utopia](https://utopia.fyi), with two modes: "xl — 1280px" and "xs — 480px".
- **Typography** — font weight, family, and size tokens, grouped in the Figma sidebar (`font/weight/…`, `font/family/…`, `font/size/…`), with two modes: "xl" and "xs".

The plugin approach is used instead of the Figma REST API because writing variables via the REST API (`file_variables:write`) requires a Professional plan. The plugin runs inside Figma itself, so it works on any plan.

## Project structure

```
.env                     # UTOPIA_SPACING URL (only config needed for the plugin flow)
build.js                 # Regenerates tokens/utopia.json from .env, compiles tokens/*.json → plugin/code.js
tokens/
  tailwind.json          # Static
  utopia.json            # Generated by build.js — do not hand-edit
  typography.json        # Static
figma-spacing-import.js  # Alternate: pushes tokens/utopia.json straight to Figma via the REST API
plugin/
  manifest.json          # Figma plugin manifest
  code.js                # Plugin code (runs inside Figma's sandbox)
  ui.html                # Collection-selection checklist shown when the plugin runs
```

## Setup

```
pnpm install
```

Create a `.env` file with your Utopia calculator URL:

```
UTOPIA_SPACING = <utopia calculator URL>
```

No API tokens are required for the plugin flow.

## Adding a collection

1. Create `tokens/<name>.json` following the schema below.
2. Run `npm run build`.
3. Re-run the plugin in Figma — the new collection appears in the selection list.

```json
{
  "name": "Typography",
  "modes": ["xl", "xs"],
  "variables": [
    { "name": "font/weight/light", "type": "STRING", "values": { "xl": "Light", "xs": "Light" } },
    { "name": "font/size/5xl", "type": "FLOAT", "values": { "xl": 120, "xs": 77 }, "description": "optional" }
  ]
}
```

- `modes` — ordered; the first becomes the collection's default mode.
- `variables[].name` — the Figma variable name; `/` creates nested groups in the sidebar.
- `variables[].type` — `FLOAT` and `STRING` are implemented/tested; `BOOLEAN`/`COLOR` should work but aren't exercised by any current file.
- `variables[].values` — one entry per declared mode.

`npm run build` validates every file in `tokens/` and fails with a clear error if a file doesn't match the schema.

## Workflow

### Updating Utopia spacing tokens

1. Adjust settings at [utopia.fyi/space/calculator](https://utopia.fyi/space/calculator).
2. Copy the full URL into `.env` as `UTOPIA_SPACING`.
3. Run `npm run build` — this regenerates `tokens/utopia.json` and recompiles `plugin/code.js`.
4. Re-run the plugin in Figma to apply the change.

### Running the plugin in Figma

1. In Figma: **Plugins → Development → Import plugin from manifest...**
2. Select `plugin/manifest.json`.
3. Run via **Plugins → Development → Import Spacing Variables**.
4. Check the collections you want in the popup, then click Import.

If a collection already exists from a previous run, delete it in Figma first before re-importing it.

### Alternate: direct REST API import (`figma-spacing-import.js`)

`figma-spacing-import.js` pushes the Utopia spacing collection (from `tokens/utopia.json`) directly to a Figma file via the REST API (`POST /v1/files/:key/variables`), bypassing the plugin entirely. This requires a Figma **Professional plan or above** (see [Key constraints](#key-constraints)).

Requires `FILE_KEY` and `FIGMA_TOKEN` in `.env` (a Figma personal access token with `file_variables:write`). `FILE_KEY` accepts either the raw key or a full file/design URL.

```
node figma-spacing-import.js --preview   # dry run, logs the payload without calling Figma
node figma-spacing-import.js             # pushes variables to Figma
```

## Key constraints

- The Figma Plugin API does not allow dots in variable names. Tailwind fractional values use underscores instead: `0_5`, `1_5`, `2_5`, `3_5`. `build.js` rejects any `tokens/*.json` variable name containing a dot.
- The Figma REST API requires a Professional plan for `file_variables:write`; the plugin approach works on all plans.
- `plugin/code.js` runs in Figma's sandbox — it has no access to the filesystem or `.env`. Only `build.js` and `figma-spacing-import.js` (both run under Node) read files.
- The `tokenCollections` array in `plugin/code.js` is generated — don't edit it by hand. The sentinel comment `// GENERATED` marks the block that `build.js` replaces, compiled from every file in `tokens/`.
- `tokens/utopia.json` is itself generated (by `build.js`, from `.env`) — edit `.env` and rerun `npm run build` instead of hand-editing it.
