# figma-tools

A Figma plugin (plus a small build script) that imports spacing design tokens into Figma as variable collections.

## What it does

Creates two variable collections in a Figma file:

- **Tailwind Spacing** — the full Tailwind v4 scale (0–96), a single "Default" mode, fixed px values.
- **Utopia Spacing** — fluid spacing tokens generated by [Utopia](https://utopia.fyi), with two modes: "xs — 480px" and "xl — 1280px".

The plugin approach is used instead of the Figma REST API because writing variables via the REST API (`file_variables:write`) requires a Professional plan. The plugin runs inside Figma itself, so it works on any plan.

## Project structure

```
.env                     # UTOPIA_SPACING URL (only config needed for the plugin flow)
build.js                 # Parses .env URL → rewrites utopiaTokens in plugin/code.js
figma-spacing-import.js  # Alternate: pushes Utopia spacing straight to Figma via the REST API
plugin/
  manifest.json          # Figma plugin manifest
  code.js                # Plugin code (runs inside Figma's sandbox)
```

## Setup

```
pnpm install
```

Create a `.env` file with your Utopia calculator URL:

```
UTOPIA_SPACING = <utopia calculator URL>
```

No API tokens are required.

## Workflow

### Updating Utopia spacing tokens

1. Adjust settings at [utopia.fyi/space/calculator](https://utopia.fyi/space/calculator).
2. Copy the full URL into `.env` as `UTOPIA_SPACING`.
3. Run `npm run build` — this rewrites the `utopiaTokens` array in `plugin/code.js`.
4. Re-run the plugin in Figma to apply the change.

### Running the plugin in Figma

1. In Figma: **Plugins → Development → Import plugin from manifest...**
2. Select `plugin/manifest.json`.
3. Run via **Plugins → Development → Import Spacing Variables**.

The plugin creates both collections in a single run. If the collections already exist from a previous run, delete them in Figma first before re-running.

### Alternate: direct REST API import (`figma-spacing-import.js`)

`figma-spacing-import.js` pushes the Utopia spacing collection directly to a Figma file via the REST API (`POST /v1/files/:key/variables`), bypassing the plugin entirely. This requires a Figma **Professional plan or above** (see [Key constraints](#key-constraints)), so it's only usable on files where that's available.

Requires `FILE_KEY` and `FIGMA_TOKEN` in `.env` (a Figma personal access token with `file_variables:write`). `FILE_KEY` accepts either the raw key or a full file/design URL.

```
node figma-spacing-import.js --preview   # dry run, logs the payload without calling Figma
node figma-spacing-import.js             # pushes variables to Figma
```

This is a step toward the project's broader goal: managing multiple variable collections with configuration to choose which ones get imported in a given run, rather than always importing everything.

## Key constraints

- The Figma Plugin API does not allow dots in variable names. Tailwind fractional values use underscores instead: `0_5`, `1_5`, `2_5`, `3_5`.
- The Figma REST API requires a Professional plan for `file_variables:write`; the plugin approach works on all plans.
- `plugin/code.js` runs in Figma's sandbox — it has no access to the filesystem or `.env`. Only `build.js` reads `.env`.
- The `utopiaTokens` array in `plugin/code.js` is generated — don't edit it by hand. The sentinel comment `// GENERATED` marks the block that `build.js` replaces.
